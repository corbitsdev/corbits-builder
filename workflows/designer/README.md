# Designer

The product designer: turns the project's documents into a clickable HTML and
CSS mockup with a `DESIGN.md` for the coder, and files it as one design
option for the person to compare.

## Where it fits

This package only declares data. It imports `@intx/agent/authoring` and
`@intx/workflow/definition`, nothing else from Interchange. The
[hub's designer entry][entry] imports it, supplies the model, director and
tools, and builds it into the workflow the [coordinator][coordinator] starts
with `design_app`, one designer per design concept. Its tools are file
reads and writes in its workspace, `check_design`, `file_design_option` and
`mail`; it has no shell. The hub also reads this package's starter, themes
and skills through its macros.

## Layout

- `src/prompt.ts`: the system prompt.
- `src/agent.ts`: `createDesignerAgent`, which requires an explicit provider
  and model.
- `src/workflow.ts`: `createDesignerWorkflow`, a long-lived mail-triggered
  step on a posix sidecar; each message is another request on the same warm
  workspace.
- `starter/`: the workspace every design begins from: `.builder/DESIGN.md`,
  `.builder/designs/index.html` and `styles.css`, and a `README.md` for the
  designer that is not filed with the design.
- `themes/`: the design themes a person can preview and pick, each a sample
  `DESIGN.md` and `designs/` bundle.
- `skills/`: skill bundles; the coder reads `react-ui` and `stack-docs`.
  `react-ui/reference/api-*.md` is generated by `scripts/react-ui-api.ts`.
- `src/skills.ts`: Bun macros that inline the starter, themes and skills
  when the hub is bundled.

## Working on it

The design contract the coder relies on is the starter's `DESIGN.md` and
token names; change them together with the [coder][coder]. `bun run check`
typechecks and tests it, and `bun run dev` runs it in a real project.
