# Publish an app to a server Builder makes at DigitalOcean

This ready-made plan makes a server for the project's saved app in the person's own DigitalOcean account and publishes the app to it, in six steps: the DigitalOcean ready check, the Publish to DigitalOcean screen, publish confirm, DigitalOcean create, DigitalOcean publish, then the DigitalOcean live check. DigitalOcean bills the person for the server every month until the app is taken down.

Run digitalocean ready first. It passes when the app says how it runs in production: how it installs, builds and starts, and which folders keep what people enter. When it fails, the app needs changing: start the coder's change of the app to make it ready to publish, naming what the check's evidence says, then run digitalocean ready again. The person does nothing for it.

Then open digitalocean account. The person chooses the server's size, each with its monthly price, and where it runs, and signs in to DigitalOcean, picking the team that pays. Their answer is what they agreed to rent.

Then run publish agreed. If it passes, the person's go-ahead for this publish stands: go on without asking again. If it fails, open publish confirm with this plan's handle; nothing is made or published without their go-ahead there, and publish confirm says how long it lasts.

Once they go ahead, start digitalocean create. It makes the server they agreed to and waits until Builder can sign in to it, which takes a few minutes, or says it is up already. When create ends blocked, relay its reason. If the reason is that the price or the team that pays changed, or that they must sign in or choose again, open digitalocean account again; it shows the price DigitalOcean asks now. Once they answer it, start digitalocean create again under the same go-ahead. If the reason names something they fix in their DigitalOcean account, start it again once they say they did. Never start create again on your own after it ended blocked: each server it makes costs the person money.

Once create reports the server up, start digitalocean publish. It readies the server the first time, publishes the app and reports the address people open it at. When it ends blocked, relay its reason. If it says the app did not install, build or start, the app needs fixing and nothing on the server does: the next step is the coder's own check or change of the app, then digitalocean publish again under the same go-ahead. If publish could not reach the server, start digitalocean create, which says whether the server is still there. If it reports the server is gone, Builder has forgotten it, and what it held and published there: open digitalocean account, where the person chooses a new server and agrees to its price, then start digitalocean create and digitalocean publish, both under the same go-ahead. Builder never makes a new server in place of a gone one without their answer on that screen. The person is never asked to work inside their server.

Once the publish reports the address, run digitalocean live. It passes while the release Builder recorded for DigitalOcean is the app as saved now, and the plan ends when it does. A newer saved version makes it lapse until that version is published too, which the person asks for anew; publishing changes goes to the same server, so only publish agreed, confirm when it fails, and publish are run again.

To take the app down when the person asks, open publish take-down with this plan's handle. It shows them that the server is deleted with everything on it, including what people entered, and that DigitalOcean stops charging for it, and asks them to agree; the screen records their answer, never you. If they agree, run digitalocean removable, then start digitalocean remove, which takes no input and checks the go-ahead again for itself. If they keep it, nothing is deleted. When digitalocean remove ends blocked, relay its reason; once they say they dealt with it, such as signing in again on the Publish to DigitalOcean screen, run digitalocean removable again and, while it passes, start digitalocean remove again without asking again. Their answer stops counting once the app is published again, so a later take-down asks again. Once the server is deleted, Builder has forgotten the server they chose too: to publish again, open digitalocean account first, where they choose a server and agree to its price again, then run publish agreed and open publish confirm when it fails, then digitalocean create, which answers that nothing is chosen until they have.
